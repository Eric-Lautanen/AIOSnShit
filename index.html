ISA Design Principles
HELIX-64 is a 64-bit RISC architecture with fixed 32-bit instruction words, designed for a new class of system where the AI model is the operating system — not a process running on top of one. There is no traditional userspace kernel API, process scheduler, or hierarchical filesystem. Every abstraction is generated on demand by the resident model and dissolved when no longer needed.

At boot, firmware initializes bare metal, then loads model weights directly into memory. A single prompt interface appears. From that point, all software — text editors, drivers, UI surfaces — is materialized by inference and executed natively as HELIX-64 instructions. No compiler. No runtime. No framework between the model and the metal.

Nodes replace the filesystem abstraction. A traditional filesystem solves three problems: where data lives, how you find it again, and how programs share it. Nodes solve all three differently — and the filesystem becomes an implementation detail beneath the semantic retrieval layer, not a user-facing concept. Persistence, indexing, deduplication, snapshotting, versioning, and transactional consistency all exist — they are simply not exposed as directory trees or file paths. Precision-critical exact data (cryptographic keys, audit records, verified hashes) lives in the hardware-backed append-only enclave ledger, addressed by content hash. Deterministic recovery is guaranteed: SAMPLE #ARGMAX replay reproduces any generated construct byte-for-byte on demand, standing in for "saved files." How you find it — not by path, but by semantic description. "The budget doc from last Tuesday" retrieves more naturally than /home/user/documents/budget_draft_v3_final.docx ever did. How programs share it — there are no isolated programs. Everything is generated from the same substrate. Sharing is structurally simple because there is one inference substrate, not many competing processes with separate address spaces.

Nodes replace executables. A traditional .exe is frozen compiled code — it does exactly one thing, the way it was written at build time, forever. A node is a capability — it knows how to generate text-editing behavior, or networking behavior, and adapts that behavior to context, hardware, and the user's learned preferences. You don't run a text editor. You invoke the text-editing capability and the system manifests whatever form of that is most useful right now. The node IS the program, the data, and the user's relationship with both — simultaneously.

Modular Node Memory: rather than one monolithic weight file, the model's knowledge is stored as a graph of small, domain-specific weight nodes — each covering a narrow capability. Nodes are loaded, hot-swapped, and continuously fine-tuned in the background as the user interacts. The first time a capability is invoked, the relevant node is built and cached. The second time it is near-instant — retrieved from NPU SRAM. Over time the system grows more capable and more personal without ever requiring a full retrain. This is how the OS learns and grows with its user.

Two-tier data model: nodes handle the vast majority of data — documents, preferences, behaviors, knowledge — which is inherently semantic. The thin remaining slice of precision-critical exact data (cryptographic keys, financial audit records, verified hashes) is handled by a hardware-backed secure enclave layer that the model reads and writes atomically. This is not a filesystem — it has no hierarchy, no paths, no permissions model. It is a flat, append-only ledger the model references by content hash.

v4.0 — Multi-Node LLM Architecture: single-socket NPUs cannot house frontier-scale models. v4.0 introduces the Distributed Node Register File (DNRF) — NRF slots that transparently reference weight shards on remote nodes via RDMA. A new DIST ISA extension (Major 0xF) adds NODE_FETCH, NODE_SYNC, SHARD_COMMIT, and VERSION_FENCE — enabling modular, per-layer training updates without stopping inference on any node. The NODE_TOPO CSR bank (0xE0–0xEF) maps inter-node latency, bandwidth, and topology, letting the graph scheduler place shards to minimize critical-path latency across the fabric. INFER_STEP is now preemptible via STEP_CHECKPOINT — no more multi-millisecond IRQ blackout windows.

v4.0 — Capability Descriptor Format: CAP (R28) now holds a 64-bit sealed capability token: bits[63:48]=ring level, bits[47:32]=domain_id (which node family owns this cap), bits[31:16]=permission mask (READ/WRITE/EXEC/AI_INVOKE/DIST_FETCH/SHARD_COMMIT/ENCLAVE_RW), bits[15:0]=generation counter (monotonic; prevents replayed sealed caps from being valid). CAP_SEAL and CAP_UNSEAL operate on this full structure — not just a ring bit. CAP_CHECK verifies all fields atomically and sets the processor flag register on pass/fail. SAMPLE #ARGMAX deterministic replay covers everything else — any generated construct reproduced byte-for-byte on demand, standing in for "saved files."

Entropy-based identity — the security model. Each HELIX-64 instance is cryptographically unique, formed from three entropy sources fused at first boot and baked permanently into NRF[0]: hardware entropy (silicon PUF, bus timing variance, thermal noise), behavioral entropy (the user's interaction patterns accumulated over time), and node weight fingerprint (the specific configuration of learned weight deltas in NRF[2]). The result is an identity that cannot exist anywhere else in the same form. Exfiltrating the weights is expensive and low-yield: they are meaningless without the hardware entropy that shaped them, the behavioral context that personalizes them, and the silicon PUF keys that decrypt them. This architecture dramatically raises attacker cost, reduces replay attack usefulness, constrains weight portability to near-zero, and binds identity to hardware entropy rather than to secrets that can be transmitted. The attack surface does not vanish — it collapses to physical access and supply-chain, which are fundamentally smaller and more tractable problems than today's remote-exploit and credential-theft landscape. Every OS instance is unique to its machine and its user. No two are alike. No stolen weight file is useful without its hardware twin.

Hardware natively supports atomic context switches, capability sealing, TLB management, graph-native dependency resolution, and transformer inference primitives — all as single instructions, designed for the day dedicated photonic or neuromorphic silicon makes real-time generative OS response indistinguishable from instantaneous.

Each NRF slot holds a 128-bit descriptor: 64-bit weight ptr + 16-bit version + 8-bit type (LOCAL/REMOTE_SHARD/REPLICATED) + 8-bit shard_id + 16-bit node_id + 16-bit epoch.
NRF[0] always resident. NRF[1] hot-swapped per domain (NODE_SWAP).
NRF[2] accumulates session deltas; flushed to distributed store by SHARD_COMMIT.
NRF[3–5] hold remote shard references; fulfilled asynchronously via NODE_FETCH.
NRF[6–7] staging slots for in-flight NODE_FETCH futures; resolved by NODE_SYNC.
Version pinning: at INFER_START, CSR[0xD5] latches GLOBAL_VERSION; all NRF reads during that generation pass must match or stall at VERSION_FENCE.
TRF — 16 × 512-bit Tensor Register File
TRF[0..15] used by MATMUL, ATTN, LAYERNORM, SOFTMAX, EMBED.
Each TRF entry is a tensor descriptor packed into a 512-bit slot: 64-bit base ptr + 32-bit shape[0] + 32-bit shape[1] + 32-bit stride + 8-bit dtype (FP16/BF16/INT8/FP32) + 8-bit layout (ROW_MAJOR/TILED_8×8/PACKED) + 8-bit quant_scale_idx + 8-bit flags + 320-bit reserved/alignment (192b active, 512b slot).
The descriptor points into NPU SRAM or main memory — TRF holds handles, not raw tensor data.
TRF[0] = active weight tensor base (from NRF[1]).
TRF[1] = system state embedding. TRF[2] = KV-cache handle.
Synchronization: TENSOR_ST flushes write-back; MATMUL/ATTN implicitly acquire TRF[0] read-lock for duration of op. FENCE_AI (SYS minor 0xF) drains all in-flight NPU ops before CPU continues.

INFER_STEP Execution Model (microcode) — v4.0: Preemptible
INFER_STEP is the atomic unit of generation — one transformer layer forward pass. It is not a monolithic op but a hardware microcode sequence:
① EMBED token_id → TRF[3]
② save residual TRF[3] → TRF[10] (pre-norm x — saved BEFORE LN runs)
③ LAYERNORM TRF[3] → TRF[4] (pre-attention norm; x safely in TRF[10])
④ ATTN TRF[4], KV=TRF[2] → TRF[5] (HW-fused QKV projection + scaled dot-product)
⑤ KV_CACHE_WR — KV entries appended by ATTN hardware
⑥ ADD TRF[5] + TRF[10] → TRF[5] (post-attention residual)
⑦ LAYERNORM TRF[5] → TRF[5] (pre-FFN norm)
⑧ MATMUL TRF[5] × W_ffn_up → TRF[6] (FFN up-projection)
⑨ ACT TRF[6] → TRF[6] (GELU)
⑩ MATMUL TRF[6] × W_ffn_down + TRF[10] → TRF[5] (FFN down + tied residual x from TRF[10])
⑪ STEP_CHECKPOINT — spill TRF state to 4 KB NPU resume buffer; check CSR[0xD8].PREEMPT
⑫ Result in TRF[5] — layer output ready for next INFER_STEP or final SAMPLE
v4.0 change: IRQs are no longer globally masked for the full microcode sequence. STEP_CHECKPOINT (⑪) is the cooperative preemption point. If CSR[0xD8].PREEMPT=1 (set by the CPU IRQ arbiter), partial TRF state spills to the per-task NPU resume buffer and the step yields. On re-schedule, INFER_STEP resumes from the checkpoint with TRF state reloaded. This eliminates the 500μs–2ms IRQ blackout window present in v3.0.

GENERATE — the macro-instruction with abort path
GENERATE Rd, Rs1, #max_tokens is a macro that loops INFER_STEP, feeds each SAMPLE output back as the next token input, checks EOS token or max_tokens limit, and returns a tensor handle in Rd pointing to the generated token sequence. This is what the OS calls for all user-visible inference — not raw INFER_STEP which is reserved for the kernel's AI dispatch layer.
v4.0 abort path: CSR[0xDA] = GENERATE_CANCEL register. Writing any nonzero value to CSR[0xDA] while GENERATE is running causes the macro to drain the current INFER_STEP to its STEP_CHECKPOINT, then return with Rd containing a partial tensor handle marked CANCELLED. The next SYSRET clears CSR[0xDA]. This allows app teardown, user cancellation, and OOM reclaim without killing the NPU tile.

Two-Tier Generation Architecture
Not everything is inference at runtime. HELIX-64 uses a deliberate split:
Stable Compiled Layer — kernel entry, interrupt handlers, context switch, spinlocks, TLB management. These are fixed HELIX-64 assembly, compiled once, never regenerated. They are fast, auditable, and deterministic.
Generated Orchestration Layer — application behavior, UI surfaces, driver logic, user workflows. These are emitted by GENERATE at capability invocation time and cached as compiled node outputs in NPU SRAM. First call: inference. Subsequent calls: cached compiled result — near-instant.
Adaptive Surface Layer — live contextual generation for user interaction, novel queries, and adaptation. Only this layer runs GENERATE at user-visible latency. Sized to be fast enough on target NPU silicon.
This prevents the "everything is latency" problem while preserving the generative OS principle.
Tensor Memory Semantics
Layout: TRF descriptors specify ROW_MAJOR (default), TILED_8×8 (for MATMUL throughput on NPU), or PACKED (quantized INT8/INT4 for bandwidth). MATMUL checks descriptor dtype and routes to the correct NPU datapath.
Quantization: Each TRF entry carries a quant_scale_idx pointing into a per-NRF scale table. MATMUL and ATTN dequantize on the fly; SAMPLE operates on FP32 logits always.
Bandwidth: NPU SRAM bandwidth target: 6 TB/s (on-die). Main memory fallback: 1 TB/s HBM. PREFETCH_AI (Cache major, Minor=0xD) preloads next layer's weights while current layer executes.
Cache coherency: TRF descriptors live in the NPU register file — not in L1/L2 CPU cache. FENCE_AI (SYS 0xF) is required before any CPU instruction reads a memory region written by TENSOR_ST. CPU-to-NPU synchronization uses a lightweight scoreboard; no full MESI broadcast.
Scheduling: INFER_STEP is dispatched to a free NPU tile; if all tiles are busy, the CPU stalls at the INFER_STEP issue boundary (visible in CSR[0xD1] = NPU_STALL_CYCLES counter).

Distributed NRF Protocol
Weight shards carry a monotonic version counter. Inference always reads a snapshot version pinned at INFER_START — so all layers of one generation pass see a consistent weight state even as remote nodes apply training deltas concurrently. SHARD_COMMIT applies a LoRA delta (rank-r adapter: W_new = W_base + α·A×B) to a shadow version. VERSION_COMMIT bumps the global counter; VERSION_FENCE ensures all NRF slots are up to date before the next generation pass begins.

NODE_TOPO CSR Bank (0xE0–0xEF):
CSR[0xE0] = total_node_count (max 16 base spec)
CSR[0xE1] = local_node_id
CSR[0xE2] = interconnect_bandwidth_GBps
CSR[0xE3] = topology_type (0=ring, 1=mesh, 2=fat-tree, 3=NVLink-style)
CSR[0xE4–0xEF] = per-node latency table (ns, 16 entries)

v4.0 CSR additions:
CSR[0xD5] = GLOBAL_VERSION (snapshot-pinned at INFER_START)
CSR[0xD8] = PREEMPT flag (bit 0 = preempt INFER_STEP at next STEP_CHECKPOINT)
CSR[0xDA] = GENERATE_CANCEL (write nonzero to abort GENERATE macro)
CSR[0xDB] = NODE_FETCH_STATUS (bitmap: bit N=1 means NRF[N] fetch complete)
Capability Descriptor — v4.0
CAP (R28) holds a 64-bit sealed capability token:
bits[63:48] = ring level (0=kernel, 1=driver, 2=trusted, 3=user)
bits[47:32] = domain_id (which NRF node family owns this cap)
bits[31:16] = permission mask (field-relative bit positions within this 16-bit field):
  bit 15=READ  bit 14=WRITE  bit 13=EXEC
  bit 12=AI_INVOKE  bit 11=DIST_FETCH
  bit 10=SHARD_COMMIT  bit 9=ENCLAVE_RW
bits[15:0] = generation counter (monotonic; prevents replayed caps from being valid)

CAP_SEAL validates and seals all fields atomically. CAP_UNSEAL re-enables the capability for a specific domain. CAP_CHECK sets the processor flag register: flag=1 if ring, domain, permission, and generation all pass; flag=0 if any check fails. A failed CAP_CHECK followed by a BNF-guarded branch is the canonical privilege gate (BNF branches when flag=0, i.e. on denial).

CAP_SEAL CAP, R1 — seal with new task's domain; increments generation.
CAP_UNSEAL CAP, R1 — restore capability for new task.
CAP_CHECK CAP, #AI_INVOKE|DIST_FETCH — verify permissions; sets flag.
